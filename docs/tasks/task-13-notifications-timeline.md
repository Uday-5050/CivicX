# Task 13 - persistent notifications and public timeline delivery

Status: implemented and verified on 17 September 2026.

## Scope

Task 13 gives citizens a durable notification inbox and keeps the report
timeline useful without exposing private institutional work. REST is the
authoritative delivery path after reconnect; socket and push delivery remain
optional follow-up work.

## Backend deliverables

- `Notification` records persist recipient, event type, title, body, payload,
  read state, and timestamps in MongoDB.
- `enqueueNotification` writes or reuses both the durable outbox record and the
  inbox record using one dedupe key. Replayed workflow events cannot create
  duplicate inbox entries.
- `GET /api/notifications` lists only the authenticated user's latest
  notifications. `GET /api/notifications/unread-count` returns their unread
  count. `POST /api/notifications/read-all` and
  `POST /api/notifications/{notificationId}/read` update read state.
- Public submission activity is still filtered by the existing visibility
  rules. Private moderation and project activity never appears in the public
  timeline.
- Public activity generated by institutional workflow events creates a
  recipient notification for the citizen owner. Notification failure is
  isolated so it cannot remove an already-recorded timeline event.

## Safeguards

- Every inbox read and write is scoped to the authenticated recipient.
- Duplicate notification keys are safe across retries and concurrent writes.
- Timeline serialization preserves the existing `{success, data, meta}`
  response envelope and redaction behavior.
